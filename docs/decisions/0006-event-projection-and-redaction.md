# ADR-0006: Append-only safe events with authorized projections

- Status: proposed
- Date: 2026-09-08
- Owners/reviewers: Pradeep Nair
- Supersedes/superseded by: none

## Context

PaymentLab must show one transaction from multiple perspectives without exposing
another session's data, provider credentials, reusable payment material, hidden
model reasoning, or unverified claims. Guided Replay must also remain
deterministic after implementation details evolve.

## Decision drivers

- One authoritative ordering for Buyer, Merchant, protocol, payment, and system
  views.
- Server-side authorization and redaction before data reaches a browser.
- Deterministic replay from versioned, non-sensitive evidence.
- Idempotent recovery from duplicate and out-of-order provider callbacks.
- An audit trail that distinguishes observed provider facts from model narration.

## Options considered

1. Store one append-only internal event stream and derive separate authorized
   projections.
2. Store a separate stream per UI perspective.
3. Send workflow/model output directly to connected browsers and persist only a
   final summary.

Option 1 best preserves a single source of truth. Option 2 risks divergence;
option 3 cannot support reliable replay, recovery, or evidence review.

## Decision

Persist versioned, append-only domain events with a monotonically assigned
per-run sequence. Each event records source, actor, safe structured data,
occurred/recorded timestamps, and evidence references. It never stores secrets,
full provider payloads, reusable tokens, PAN/CVV, or hidden reasoning.

All browser feeds and public recordings are generated by named server-side
projection functions. A projection accepts an authenticated session or a
versioned public-recording capability, applies an explicit event allowlist and
field-level redaction policy, and emits a versioned view model. Model text is
labeled as narration and cannot upgrade payment/order state.

Raw Stripe webhook bodies are retained only for the minimum verified processing
window in restricted storage, separate from public/domain events. The webhook
receipt stores safe identifiers, verification state, a payload digest, and the
business application result.

## Consequences

- Every perspective can be reconstructed from the same ordered record.
- Projection and redaction versions become release-controlled contracts.
- Storage and retention must distinguish domain evidence from restricted raw
  callback material.
- A physical event schema, representative fixtures, and cross-session negative
  tests are required before this ADR can be accepted.
